# 两侧先放与伸展极限

2026-10-29 真机入口修正：日志中的策略应为
`p2_occupied_side_aware_entry_v6`。对侧已有箱子时，沿目标侧可用门洞通道入舱，
不再先强制居中靠向已放好的蓝箱；该模式取消旧的“第四箱下降9cm再抬高”特判。
经过的箱体和底座仍决定净空，不再为没有经过的蓝箱额外抬高。
IK在原初值和小幅扰动均无解后，增加肘部伸直的数值求解初值；这不是直接发送
伸直关节命令。诊断 `ik_attempts.seed_kind=straight_elbow` 可确认已尝试该分支。

本次检查调用同一个真机入口生成器，从示教P2关节角和名义吸附变换开始，
第四箱整机IK及碰撞检查460帧通过；八箱箱体几何采样与执行器相关62项测试通过。
这不包含现场实测抓取偏心，也不代表八箱真机路线全部验收。
拉取后重新构建 `luggage_planning`，重启笔记本上的规划后台和操作台；仅替换JSON
不会更新入口生成器和IK服务代码。

八箱顺序采用两侧堆先装、中间堆最后装；每堆仍然自下而上：
红、银、蓝 → 青铜白、黑、灰 → 粉、小灰。几何目标、尺寸和三层上限不变。
`policy/prepare_sides_first.py` 重算新顺序下绕开已放箱子的路线；仅生成几何计划，
必须通过完整 Newton 编译检查才能生成 READY 回放包。

真机遇到纯 IK 无解（MoveIt -31）时，搬运中间点和 pre_place 会沿当前 TCP 到
目标的方向寻找最远可达点，再执行完整轨迹规划。目标姿态、现有机械限位以及
现场选择的碰撞检查配置继续生效。不会因为数值求解失败直接跳过一个箱子。
抓取接触、最终下降落位、复位原路返回不缩短目标。确实没有可达候选、服务故障
或取消请求仍会停止；不会把未到达的最终放箱位置当作成功。

抓取目标优先使用当前关节状态的精确 IK 解；数值求解失败时才尝试其他种子，
伸直关节仅作为最后一个求解初值，不是直接下发的目标。现场关闭软件碰撞检查时，
权限矩阵使用实际展开的机器人模型全部连杆，避免遗漏相机和末端安装座。

`/motion_planner/last_boundary` 和会话日志中的 `reach_projections` 包含
requested、achieved、shortfall_m。动作结果的 settle_json 同时携带实际完成的
搬运路点，返回记录据此更新。发生缩短后不能用原请求路点冒充实际经过的位置。
连续搬运路线中间点到达可达边界后，后续中间点若仍无精确 IK 解则跳过，继续
尝试后面的收回点；遇到下降点时先尝试在当前水平位置精确下降，再向目标靠近。
最终 pre_place 目标仍须精确到达，否则停止而不进入放置。
执行故障、取消、非 IK 错误不因这个规则跳过。跳过的点在回程记录中不记作已走过。

Newton 使用真实 URDF、关节限位和碰撞网格，沿肩部到目标的射线寻找外缘；
搬运可缩短，接触不缩短。`probe_maximum_reach.py` 单独验证不可达目标的伸展结果。
真机用实时当前 TCP 作为搜索起点，不能承诺与 Newton 得到同一组关节角。

验证状态和路径包以当前 evidence/result/READY 为准。尚未通过全轨迹验证的计划
不应替换正式回放包。仿真通过不代表现场 MoveIt 轨迹或视觉抓取已经验证。

地面 Newton 接驳采用保持工具姿态的门外笛卡尔直线，再对准原舱内入口。
第四箱青铜白的原关节扫动曾触碰门框候选并导致搜索超时；保存失败状态后的
