# 真机按钮操作台（现场调试模式）

保持 Orin 感知、笔记本机器人后台两个终端运行，第三个终端启动常驻操作台。
浏览器每次按“开始 Pick”，执行一箱：观察/检测 → pick → place → 松吸确认 →
放置点上退 → 沿现场路径退舱 → 回到照片固定关节位 → 等下一次点击。
最后一箱也归位，然后显示 COMPLETE。无需逐箱重启脚本或单独运行 place。

网页新增“运动速度”滑块（10–100%）和“应用速度”按钮：待机或故障停稳后可改，
运动中禁用，下一次动作生效。100%为当前规划正常速度：真机 launch 速度比例0.30，
关节速度上限约27°/s（原13.5°/s）；加减速仍不超过20°/s²。
降低百分比会延长整条轨迹，不能当急停。读回成功才显示“已应用”；服务失败
会显示错误，不把滑块位置冒充已生效值。重启操作台后先重新应用所需速度。
同一搬运阶段的路径点在一条完整规划轨迹中连续通过，回程同样连续反向通过路点。
抓取、放置下降、松吸确认和上退保留必要停止，不跨这些边界拼接。
本版需重新构建并重启 L1 规划/执行后台和 L2 操作台；只刷新网页不会更新运行代码。

### 默认连续录制

L2每次启动自动生成`<journal>.telemetry.<session>.jsonl`，独立于可覆盖的操作日志和
单箱重试日志；新的会话编号保留旧录制。无需额外命令，不会创建第二个CPS连接。
网页顶部显示文件路径、缺少的数据流、超过2秒未更新的数据流及磁盘写入错误。

录制包含实际关节角/速度、电流（A，不是Nm）、控制器命令关节角、TCP、吸盘DI0/DO0/DO1
和状态、控制器FSM/HRIF错误、规划边界、完整动作请求、完整FJT点及限幅后的ServoJ网格、
TF、ROS错误和运行时参数变更。无效读取用空值/有效标志表示，不补零、不插值。
每行保留接收墙钟/单调时间及原始消息时间；CPS采样携带读取序号、采样单调时间和
速度来源。关节计时器目标100Hz，实际频率受CPS读取和调度限制，不能假定每10ms必有一帧。
指令网格记录代表计划发送值，不证明每点实际执行成功；需对照反馈和失败索引。

同名`.sources.zip`保存启动时部署的Python源码和关键配置（包括未提交修改）；
正常退出另写`.summary.json`，统计各流样本数/时间范围/最大接收间隔。
一般每0.5秒落盘；收到故障日志、执行器事件及操作事件时立即刷新并fsync。
强制断电/kill仍可能丢失最后一小段尚未落盘的数据。不要覆盖、删除失败会话。
发厂家时一并提供telemetry JSONL、sources ZIP、summary JSON、原journal和单箱JSONL。
这版需同时重启L1和L2，缺少`/elfin/cps_telemetry`表示L1可能仍在运行旧版。

连续搬运可能超过旧的90秒单段等待时间。操作台现在用规划/执行/停稳反馈检测失联，
收到有效反馈时继续等待最终结果；规划器仍按实际轨迹时长限定执行期限。
不能把反馈当作完成信号；真实执行失败仍保吸并要求显式恢复。
故障信息同时显示原始阶段和原因，例如`PLACE_CARRY_FAULT [pre_place]`，不只显示`exit 10`。

除记录路径的反向回程外，`cartesian fraction below1`不再直接拦停：笛卡尔路径不完整时自动改用完整目标规划，
按原顺序经过全部路点，不执行部分路径，也不跳过门框中间点直接去终点。
备用路径保留碰撞、关节/腕部检查，可能偏离原直线并在路点停稳；失败仍要求恢复。
反向回程不使用此备用路径，必须完整沿记录路点做笛卡尔规划，否则停止。
下降先尝试细分笛卡尔规划，仍不完整才走备用规划；实际放置位置确认通过后才松吸。

这是 `site_commissioning_v1` 调试入口，不是完整生产编排：没有自动扫舱、
实测放置验收、货舱地图提交和在线生成下一箱目标。
操作员每次勾选确认，包含检查上一箱放置、当前场景和上料区域。
已放箱子保留“目标位置 + 本轮配置尺寸”的**预期碰撞占位**供 MoveIt 避障；
它不写入实测货舱地图，也不能证明实际箱子没有偏移。放偏时停止并修正场景，
不能继续沿用占位。此入口尚未经过真机现场验收。

## 现场配置

复制 [默认配置](../config/loading_cycle.site.template.json) 到 `/ABS/site/loading_cycle.json`。
坐标依据是用户提供的 `deployment_ws/config/scene_tf.loading_site.yaml`：
底座 yaw `-90°`，面对航空箱时基座 `+X` 向左、`+Y` 向后、`+Z` 向上。
名义右手边上料点为**基座 `(-1.6, 0)`**，对应 world 约 `(0, 1.6)`；箱底 world `z=0`。
本次部署默认采用**八箱三堆**路线，舱内动作源包为
`policy/demo_data/measured8_spaced_inside_full/`。顺序和尺寸：红 59×37×24、银 56×36×21、
蓝 55×36×23、粉 65×41×24、小灰 41×40×22、青铜白 67×43×27、黑 67×43×26、灰 55×36×23 cm。
地面接驳仿真仅完整通过前三箱；第四箱停在回程，余下未运行，现场按用户要求暂时假定可行。
第三堆底箱贴平底与斜面的交界，边界没有余量；详见 [八箱状态](measured8_status.md)。
**箱子上料点与 EEF 等待位分开**：箱子仍在基座 `(-1.6, 0)` 地面；
EEF 归位使用下文的照片固定关节角，原导出观察位只保留为源路线记录。
实际抓取接触点由原视觉 Pick 决定。
上料点允许偏移，继续使用原视觉 Pick。成功后保持吸附，按实际抓取变换生成
外侧抬起 → 在底座外侧收臂 → 抬至箱底高于底座顶面 15cm → 下述居中入舱路线。
附加 5cm 底座箱体净空检查。按现场要求，此调试入口的箱体尺寸统一取本轮配置，
视觉只提供抓取顶面、位置和朝向；抓取偏心由封吸后的工具 TF 推算。
新箱型在原供料位附近较低的路径前缀由高位接驳绕过：先横向到安全入口上方，再垂直下降接原入舱轨迹。
15cm 高度用于横向接驳；下降和入舱仍保留底座 5cm 余量及完整场景碰撞检查。
每箱完成后归位，操作台显示下一箱的颜色与尺寸；八箱完成后显示 COMPLETE。
不自动重复同一放置目标，避免堆叠覆盖。
航空箱的平移和完整 roll/pitch/yaw 均来自该 YAML，不能再使用此前底座 `+90°` 的配置。
`assumptions` 保存来源和哈希，并不意味着执行过现场验收。
O1 的 `orin_perception.sh` 和 L1 的 `hardware_pick.sh` 默认加载上述文件；
如果显式传 `scene_tf_config`，两机都应指向各自仓库里的这个文件。
它只导出位姿供真机重新规划，不直接回放仿真关节轨迹。

- `observe_tool_pose`：工具 `suction_contact_frame` 在现场 `world` 中的等待/观察位，
  单位 m、姿态 xyzw。应能看见地面上料区，并让开人工上料空间。
- `cycles`：按执行顺序每箱一项，当前默认八箱；启动时冻结整个列表，
  不在线计算或重读目标。若现场布局不同，先把位姿转换到实际 world。
  `expected_demo_input_dims_m` 是本轮 MoveIt 碰撞箱体、携箱检查和预期占位的尺寸来源。
  字段沿用旧名，不能用视觉报告的尺寸覆盖。`payload_geometry_source=configured_cycle`
  显式标记此调试模式；缺少每箱尺寸时拒绝 Pick。尺寸不是对实体箱子的自动身份校验。
  `box_label` 标识本次应上料的实体箱子；必须按页面顺序上料，程序没有自动颜色身份识别。
- `place_target`：箱子中心目标，遵循 [放置接口](policy_place.md)。
  `via_box_poses` 是携箱入舱路径中的箱中心位姿。
- `exit_tool_poses`：保留的源 demo 空工具退舱位姿，用于离线对照。
  正常运行及掉箱复位优先反向经过本轮已经完成的携箱停留点，回到 Pick 抬起后的停留位，
  再去照片固定关节位。去程和回程恢复原有密集逐点停稳；
  反向段要求完整笛卡尔路径；规划不完整时停止，不执行部分路径，也不通过逐点关节规划改道。
  不反向执行放置下降，避免工具再次降入刚松开的箱子。失败时保留未完成的回程进度。
  尚未完成 Pick、没有本轮回程记录时直接通过 MoveIt 规划到固定关节位。

放置中心和路线来自配置；初始化、放置后返回和掉箱复位都使用照片固定关节角，J1～J6（度）：
`188.299, -135.510, -95.754, -36.132, 91.924, 12.500`。
唯一数值定义在 `commissioning_home.py`；不通过 XYZ/相机朝向求 IK，
也不再绕去原名义等待位后才到终点。MoveIt 仍规划并检查完整关节路径。
松吸目标沿箱体上方向增加 5mm 间隙，避免舱底网格的毫米级
起伏导致接触碰撞。仍须整段规划成功、实际工具到位、再松吸及确认 DI0。

上料坐标是人工放箱区域的约定；抓取仍使用本轮视觉检测，不按该坐标盲抓。
初始化现在可选：点“初始化归位”才通过 MoveIt 运动到照片中的固定关节位；
也可以点“跳过初始化，从当前位置开始”，只检查后台、场景和空工具状态，
不发送运动、检测或真空命令。跳过后仍需单独点击 Pick，第一箱从当前姿态观察/抓取；
之后每箱完成的自动回程仍回到配置的观察位，不会省略。
初次运行前需现场检查场景、工具、路径和可达性。初始化不会清空场景或已放箱子占位；
重新开启会话前需核对留存场景与实际货舱。

## 笔记本 L2 命令

先按 [真机操作文档](real_robot_runbook.md) 启动 O1、L1。笔记本在 Jazzy 环境重新构建：

```bash
cd /ABS/RoboticArm
source deployment_ws/scripts/env_jazzy_real.sh
colcon build --symlink-install --packages-select luggage_planning
```

在 L2 启动：

```bash
cd /ABS/RoboticArm/deployment_ws
mkdir -p /ABS/site/runs
cp config/loading_cycle.site.template.json /ABS/site/loading_cycle.json
bash scripts/run_loading_console.sh \
  --site-profile /ABS/site/loading_cycle.json \
  --journal /ABS/site/runs/loading_001.jsonl
```

本次必须更新旧路线：将新模板覆盖到实际使用的 profile 路径，重启 L2。
只 `git pull` 不会更新仓库外已经复制的 `/ABS/site/loading_cycle.json`。
确认 JSON 有 `carry_entry.strategy=outside_retract_high_lift_v1`、名义 feeder `[-1.6,0]`、
`cycles` 当前为八项。此前四箱、十箱 profile 不会自动换成新路线。
同时重启 O1、L1 加载新 YAML；只更新 L2 不能修正旧机器人 TF。
需要重新从同一 demo 导出默认配置时，在仓库根目录用 Newton Python 执行：

```bash
python policy/export_hardware_loading_profile.py \
  --output /ABS/site/loading_cycle_from_demo.json
```

`runs` 目录需存在；允许复用同一个 `--journal` 文件，启动时覆盖旧的会话日志。
每箱另存 `<journal>.box001.jsonl` 等明细，同一箱重试时覆盖该箱明细，
不再因为 `File exists` 阻止开始下一次尝试。未执行箱子的旧明细不会自动删除。

可用 `--start-box N` 从配置中的第 N 箱开始（从1编号，默认1）。例如从蓝色箱开始：

```bash
bash scripts/run_loading_console.sh \
  --site-profile /ABS/site/loading_cycle.json \
  --journal /ABS/site/runs/loading_001.jsonl \
  --start-box 3
```

当前八箱序号：1红、2银、3蓝、4粉、5小灰、6青铜白、7黑、8灰。保留原箱号、对应尺寸和放置目标，
从第3箱开始执行第3至第8箱；页面本轮进度从 `0/6` 开始。
跳过项不计入本轮完成数，也不会凭空创建之前箱子的占位或恢复旧故障状态。
启动仍需初始化或跳过初始化，再单独点击 Pick；参数本身不会触发机械臂动作。


在笔记本浏览器打开 `http://127.0.0.1:8765`：

1. 启动为 WAIT_START，不触发检测、运动或吸盘操作。
   可先勾选确认并点“坐标方向测试”：按基座 `+X/-X/+Y/-Y/+Z/-Z` 各走 2cm，
   每个方向后返回点击时的工具位姿，保持姿态。全程空工具、吸盘关闭、完整 Cartesian 路径，
   不做箱子检测或 Pick。每段验证到位后才继续；失败锁定，不盲目追加复位动作。
   在 WAIT_PICKUP_READY 也能执行此可选测试。完成后仍需人工观察确认方向并单独授权 Pick。
2. 检查现场并勾选确认，选择“初始化归位（可选）”或“跳过初始化，从当前位置开始”；
   对应动作/检查成功后进入 WAIT_PICKUP_READY。
3. 人工上箱、退出运动范围，检查并重新勾选，点“开始 Pick”。
4. 执行中按钮禁用。页面顶部卡片显示任务阶段、CPS FSM（33 StandBy / 21 碰撞等）、
   最近 HRIF 命令和错误码（40071 缓冲未初始化、40025 不在 StandBy）、真空状态，
   以及最近 ServoJ 事件。原始 JSON 折在页面底部。这些数来自
   `/elfin/hardware_status`，需 L1 `trajectory_executor` 已重启发布。
5. 成功归位后产生新请求，等待下一箱。网页刷新不会重发 Pick。

每次确认带 request_id 和 schema_version；忙碌、重复、过期请求不排队。
控制台仅绑定本机，关闭网页不会停止后台动作。
不要同时启动旧的单箱执行命令或其他运动操作台。

## 故障

检测、吸附、携箱、释放、碰撞场景更新、退舱、归位任一失败均锁定 FAULT。
不自动下一箱、重试或在携箱故障时松吸。网页提供「停止并恢复待机」以及明确授权的
「松吸掉箱并回位」，见 [Pick 恢复说明](pick_recovery.md)。恢复不会清除历史故障记录。
释放未确认不接着退舱；空工具/真空关闭未确认不初始化或开始下一次 Pick。
动作超时请求取消，但取消请求不证明硬件已停。

新 console 在初始化、方向测试和每段运动前校验实际 base/container TF 与 profile，
拦截旧 `+90°` 底座或其他场景不一致。`(-1.6,0)` 仅为名义上料点，不要求精确摆放；
不再使用旧 profile 的 20cm 半径或地面高度偏差拦截。实际箱位、候选抓取、可达性和吸附由原视觉 Pick 负责，
原 Pick 的接近、吸附、抬起及失败反退不套用 console 的固定短段限制。
成功 Pick 并完成抓取反退后，所有箱子保持吸附，依次走示教器照片的关节目标
P1 `(212.133,-104.860,-89.370,-71.821,91.730,38.169)°`、
P2 `(276.291,-68.652,-122.978,-75.087,87.203,102.188)°`。
P1 由 MoveIt 规划到固定关节目标；P1→P2 按六轴角度单调插值，最多每 1°
检查一个关节状态，并在整条路径都通过附着箱体碰撞检查后才执行，避免自由规划绕路。
任一步失败立即保留吸附和检查点，不松吸或跳过该点。P2 到位后重新读取
`world -> suction_contact_frame` 的新鲜实测 TF，从该位置生成后续放置路线；
先在 P2 的门外纵向位置对中，再向舱内推进；不回到旧的名义门外起点。
不再执行原来的 pedestal/high-lift 抓后接驳。若中途恢复，会从未完成的 P1/P2 继续。
后续 place、退出及最终观察位保持不变。普通段位移/转角启发式现在只告警、不拦停；
模板设 `enforce_segment_heuristics=false`，旧 profile 没有该字段时也默认只告警。
初始化和最终归位交给 MoveIt 自由空间规划，不再用 TCP 直线距离上限拦停。
原 45° 单段关节转幅限制已在真机 launch 中关闭（`max_segment_joint_excursion_rad=0`）；
原 `3 rad/m` 笛卡尔转动比拒绝分支已经删除，只记录诊断/告警；
即使旧 launch 仍传 `cartesian_excursion_rad_per_m=3`，更新后的执行器也不会因比值超出而中断。
这两项需要重新构建并重启笔记本 L1，运行中的 executor 不会因 `ros2 param set` 自动重建。
工具 TF 仍必须为最近 2s 数据。MoveIt 机械限位、碰撞、腕部翻转检查、失吸停机和释放确认保留；
硬件 launch 的速度/加速度比例为30%/30%，实际加减速仍封顶20°/s²。
时间分配比较整段缩放与局部单调三次插值，选择更短且满足解析限幅的一种；
保留所有路点，急转处局部减速，避免一个转折拖慢整段搬运。
这些限制不替代现场方向观察和实体急停。

实体急停是停止手段；网页关闭、Ctrl-C 和 HTTP 均不是急停。

默认执行后端已改为 ServoJ：使用已有 StartServo/PushServoJ，20ms 周期、100ms lookahead。
这需要更新并重启 L1；旧窗口仍会继续用启动时的后端。需要旧后端时显式传
`execution_backend:=waypoint`。位置/姿态仍由 MoveIt 规划，ServoJ 负责平滑发送关节轨迹。
搬运 via/pre-place 可从失败的 Cartesian 规划回退到完整 MoveIt 终点规划；最终下降仍要求
fraction=1.0，并在失败时尝试更细采样，不执行部分路径、不提前松吸。
中断执行中的控制台不会追加归位或松吸；需现场明确恢复，保留 journal、trace。
此调试入口不自动推进感知 tracker 实例生命周期；检测仍返回旧实例时，
应先按现场感知流程更新。现有身份校验仍生效。

### IK -31 与中断恢复（2026-10-28）

`IK failed error_code=-31` 来自 MoveIt 的 `GetPositionIK`，并不是控制器的
ServoJ IK 拒绝。同一个目标先用当前关节求解，再用两组附近的肩肘关节种子求解，
每次最多2秒；种子不作为运动指令，目标朝向、腕部分支保护和碰撞检查保留。
只有最终 `place_descend` 的完整目标重规划仍返回 -31 时，才依次尝试原释放点
世界Z上方2.5、5、7.5mm的完整直线下降；XY和朝向不变，不执行部分轨迹，
执行器/控制器故障不触发这类重试。仍需通过原有10mm位置、2°朝向检查才松吸。
原有5mm释放间隙之外最多增加7.5mm；松吸后的预期箱体障碍物使用落稳后的配置位置，
不会悬浮在释放高度而挡住下一层。这些障碍物仍是预期模型，不代表实测落位。

网页新增「保持吸附回位」和「继续当前箱」。前者反向经过本轮记录的已完成携箱路点，
再以附着箱体参与规划返回照片固定关节位，保持吸附、保留当前箱号；后者继续未完成段，
不会重做已确认完成的抓取。携箱回位后继续，会重新走本箱携箱路线。
若已经确认松吸，则只修复场景状态、执行上退和空载返回，不重复松吸。
恢复需要新的现场确认，并要求2秒内的物理 `/vacuum/io`；携箱要求
DI0=1、DO0=1、DO1=0，空载要求DI0=0、DO0=0，模型仍须确认附着。
恢复失败会再次停止；不会自动忽略碰撞或清除记录。

进度保存在 `<journal>.checkpoint.json`（可用 `--recovery-file` 指定），按运动段和
释放边界原子落盘。复用journal启动时读取该检查点，恢复箱号和故障状态；启动本身
不执行动作。配置文件SHA256必须一致。已完成/明确掉箱复位的周期可以用
`--new-cycle` 重开并重新应用 `--start-box`；未完成持箱任务不能这样丢弃。
改变profile时使用新的journal。新周期不会删除MoveIt里已有的箱体，现场须与场景一致。
旧版产生的失败没有检查点，不能据旧JSONL直接启用此恢复流程。

此变更修改L1规划代码和L2操作台，编译后须重启L1/L2才能生效。
验证覆盖离线控制流、求解器请求和检查点重启；未完成真机带载恢复验收。

### 统一居中进门（2026-10-28）

所有箱子共用 `CenteredDoorwayEntry`：P2 到位后从实测箱体位置在门外对准门洞的横向中点，
在门洞中间20cm的通道内选择最靠中的可降低路线，最多偏离几何中点10cm；
沿门洞法线直进，整个箱体尾面越过门框至少15cm后，才向配置的放置列横移。
横移时只计算实际经过的前序配置箱体，箱底高于这些箱子顶面5cm，
水平避开高摞时保留至少3cm投影余量，并保留底座抬高要求；
相较初版统一飞越最高箱子的高度，本版最多下调8cm，避免无必要地贴近上门框。
抵达本列后垂直降至pre-place，再执行原有最终下降/松吸/上退。
P2 之后的居中点保持在 P2 的门外纵向位置并前进约1cm，
不再后退到旧版按箱体外接球计算的门外起点。
门洞位置来自现场 `container_link` TF 和profile的 aperture，使用完整箱体尺寸，
不是只看吸盘中心。这里不假定实体活动门板已被测量。

此规则替换所有箱子原有的 `via_box_poses` 搬运段；最终放置位置、朝向、配置尺寸
不变，仍通过实测抓取变换得到TCP轨迹。入口采样间距最多5cm，连续通过密集路点，
不压缩成7～8个点；完成后反向返回也记录这些新路点。新路线的整机规划、碰撞、
腕部检查继续由MoveIt执行，完整箱体离线检查不等于真机整机验证。

重新编译并重启L2后，新Pick会采用新入口；无需改动仓库外profile的放置位置。
已经保存的旧中断路线不会悄悄更换：使用旧入口或旧高度规则的CARRYING检查点必须先「携箱回初始位」再
「继续当前箱」，从实测初始位重新生成新路线；或者明确掉箱复位后重新Pick。
携箱返回本身仍需完整碰撞检查；无法返回时保持故障，不自动松吸。
