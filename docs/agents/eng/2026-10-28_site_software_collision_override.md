# Operator-requested software collision override

Base revision 75b5311. User requested all software collision detection off for the current real-cell loading workflow and stated that they will stop the arm manually if needed. The real-cell launcher now sets `software_collision_checks=false` on motion_planner; other entry points retain the default true value. The motion planner skips occupancy injection and sweep, requests Cartesian and IK solutions without collision avoidance, and before each probe or motion applies an allowed-collision matrix that permits all current pairs and defaults future objects/links to allowed. The console skips its doorway and per-segment software collision gates. Joint limits, trajectory completion, wrist checks and controller firmware protection remain separate.

Read-only evidence before this change: the latest loading_102 sixth-box faults include ServoJ ExecuteTrajectory -4 and a P2 resume start 2.8 cm off the taught line. Those are not software collision faults and will not be repaired by this override. No robot movement was commanded by the agent. The live MoveIt ACM must be inspected after restart to confirm the override applies to the actual scene.
